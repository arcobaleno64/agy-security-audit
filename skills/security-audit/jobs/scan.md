# Job Specification: `scan` (Standard Repository Security Scan)

## 1. Objective & Baseline
Aligned with multi-stage security assurance standards, the `scan` job conducts a comprehensive, structured security audit of an entire repository or explicitly scoped directories.
Its core objectives are:
- **Exhaustive Directory Accounting**: Derive top-level directory categorization directly from filesystem ground truth.
- **Component × Vulnerability-Family Discovery**: Replace naïve global sink grepping with component-aware threat surface exploration.
- **Auditable Canonical Artifacts**: Produce deterministic `scan-manifest.json`, `coverage.json`, `findings.json`, SARIF 2.1.0, and Markdown reports.
- **Audit Intent**: Operates primarily under `auditIntent: DISCOVERY` (or `REGRESSION` when verifying fixes across repository scope).
- **No Finding Quota**: Zero findings in a fully reconciled scan is a valid outcome (`canDeclareClean: true`).

---

## 2. Scan Invariants
1. **Deterministic Inventory & Directory Accounting**:
   - Every top-level folder must be explicitly categorized (`SCANNED_RUNTIME`, `SCANNED_BUILD`, `SCANNED_CI`, `SCANNED_AGENT_CONTEXT`, `SCANNED_TEST_EXECUTABLE`, `EXCLUDED_VENDORED`, `EXCLUDED_GENERATED_VERIFIED`, `EXCLUDED_STATIC_ASSET`). Test surfaces are never blanket excluded.
   - Any unaccounted folder halts the run with `UNACCOUNTED_DIRECTORY_ERROR`.
   - The directory manifest cannot be hallucinated by the model; it is generated by `build-inventory.mjs`.
2. **Component × Family Discovery Matrix**:
   - The scanner explores intersections between identified components (e.g. `API`, `Auth`, `FileHandling`, `PluginSystem`) and vulnerability families (e.g. `authz/tenancy`, `injection/query`, `network/SSRF`, `filesystem/path`, `parser/deserialization`, `secrets/crypto`).
3. **Canonical Verification Panel**:
   - Candidates are subjected to the 3-lens verifier panel (`REACHABILITY`, `DEFENSES`, `IMPACT`).
   - Model cannot self-assert final verdicts; `finalize-scan.mjs` executes deterministic disposition derivation under Default-Deny.

---

## 3. Execution Pipeline
```text
[Repository Root / Scoped Path]
           │
           ▼
[build-inventory: Deterministic FS Directory Manifest]
           │
           ▼
[threat-modeler: Component & Threat Surface Modeling]
           │
           ▼
[Component × Family Discovery Passes]
           │
           ▼
[3-Lens Verifier Panel: Reachability, Defenses, Impact]
           │
           ▼
[finalize-scan: Canonical Findings, SARIF, Markdown, JSON]
```
